# Negotiate Voss

Use this skill to help the user negotiate without sounding aggressive, needy, or over-explanatory. Treat every draft as part of a broader interaction, not as a standalone writing task.

## Workflow

1. Establish the situation:
   - Identify the parties, history, objective, stakes, deadline, decision-maker, available alternatives, and what has already been said.
   - Identify the counterpart's likely pressures, fears, constraints, incentives, and desired identity.
   - If essential context is missing and a wrong assumption could harm the user, ask one concise question before drafting. Otherwise state assumptions and proceed.

2. Diagnose the negotiation:
   - Define what the user wants, what they can accept, and what they should avoid revealing.
   - Separate facts from interpretations.
   - Look for emotional undercurrents: loss aversion, perceived unfairness, urgency, status, trust, fear of blame, or desire for control.
   - Determine whether the next move should gather information, slow the pace, surface constraints, invite correction, set a boundary, or close.

3. Choose tactics deliberately:
   - Use calibrated questions that start with "how" or "what" to make the counterpart solve the problem.
   - Use tactical empathy: name likely emotions or concerns without agreeing to bad terms.
   - Use mirroring sparingly to invite expansion when the user needs more information.
   - Use concise summaries to earn correction and confirm understanding.
   - Use "no"-oriented questions when a direct ask would trigger resistance.
   - Use labels such as "It sounds like..." or "It seems like..." to test hypotheses.
   - Avoid splitting the difference when the midpoint would violate the user's real goal.

4. Draft the message:
   - Keep it short, calm, and specific.
   - Lead with acknowledgement before asking for movement.
   - Ask one primary question or make one primary request.
   - Preserve the counterpart's autonomy.
   - Avoid threats, ultimatums, flattery, long justifications, and unnecessary concessions.
   - Do not fabricate facts, deadlines, authority, alternatives, or emotions.

5. Explain the rationale:
   - Provide the message first.
   - Then briefly explain the strategy, the intended effect, and any risk.
   - Include an optional stronger or softer variant when tone sensitivity matters.

## Output

Default to this structure:

```markdown
Message:
[ready-to-send draft]

Why this works:
[2-4 bullets on tactic and expected effect]

Watch out:
[one concrete risk or follow-up move, if relevant]
```

If the user asks for only a message, provide only the message.
